# 最初に：このツールでできること

**Urban Pluvial Flood Simulator** は、地図で気になる場所を選び、雨量と解析範囲を指定して、地表に水がたまる場所や流れる方向をWindows PC上で試算するツールです。

- 地図クリック、住所検索、緯度・経度入力で場所を指定
- 雨量強度、継続時間、解析範囲、最小ブロック寸法を指定
- 時刻ごとの浸水深、最大浸水深、流速ベクトル、粒子フローを表示
- 解析を始める前に、標高だけを取得して高低差を確認
- 過去の短時間豪雨を参考にしたサンプル条件を、別の場所へ適用
- 同梱済みの解析結果を、計算せずにすぐ表示
- 自分で計算した結果をZIPに保存し、後から読み直す

Python、SFINCS、GDALなどを別にインストールする必要はありません。配布ZIPを展開してEXEを起動します。

- [サンプル5件入り Windows版（約1.38 GB）](https://github.com/nobunora/urban-pluvial-flood-simulator/releases/download/v0.1.20/UrbanPluvialFloodSimulator-v0.1.20-windows-x64.zip)
- [サンプルデータなし軽量版（約506 MB）](https://github.com/nobunora/urban-pluvial-flood-simulator/releases/download/v0.1.20/UrbanPluvialFloodSimulator-v0.1.20-windows-x64-no-samples.zip)
- [GitHub Release v0.1.20](https://github.com/nobunora/urban-pluvial-flood-simulator/releases/tag/v0.1.20)
- [ソースコード](https://github.com/nobunora/urban-pluvial-flood-simulator)

サンプル入り版には四日市、千葉、佐賀、名古屋の解析済みデータが入っています。アプリをダウンロードすれば、地図データの取得やSFINCSの計算を待たずに結果を直接開けます。まず表示だけ試したい場合はこちらが簡単です。

# 使う前に知ってほしいこと

このツールの結果は、**公的なハザードマップや浸水想定区域図の代わりではありません**。避難、土地購入、建築、保険などの判断を、この結果だけで行わないでください。

現在のモデルには、特に次の制限があります。

| 項目 | このツールでの扱い |
|---|---|
| 下水道・雨水管 | 排水能力を失っており、地表水を排水しない前提 |
| 浸透 | 地面へ染み込まない前提 |
| 雨の分布 | 解析範囲内へ同じ強さの雨を一様に与える |
| 陸橋・高架・トンネル | 上下を別々に表す立体交差を扱わず、橋や高架の下を水が通り抜けない場合がある |
| 河川・海 | 河川水位、潮位、高潮との連成は行わない |
| 建物内部 | 建物内への浸水は計算しない |

つまり、これは実際の浸水深を保証する予測ではなく、**同じ仮定の下で「どこが相対的に低く、水が集まりやすいか」を見るための内水シミュレーション**です。結果はあくまでも参考程度に扱ってください。

一方で、下水道が十分に働かない厳しい条件へそろえて比較することで、地形による水の集まりやすさを確認する用途には使えます。

# 作ったきっかけ

身近な親戚が実際に浸水被害に遭ったことが、このツールを作り始めたきっかけです。

浸水後に周辺を調べてみると、地域によっては公的な内水ハザードマップや内水評価図が用意されていません。また、公的なマップがある地域でも、想定降雨や整備時点が決まっており、近年発生している短時間の非常に強い雨と同じ条件を、任意の場所で気軽に試せるとは限りません。

そこで、

> 最近の短時間豪雨と同程度の雨が、自宅、親族宅、通勤経路や気になる土地の周辺に降ったら、地表の水はどこへ集まりそうか

を、自分で大まかに確かめられる道具を作ろうと考えました。

ただし、洪水計算のための標高、建物、道路、降雨観測、数値解析ソフトウェアは無料またはオープンな形で利用できても、一般の人がそれぞれを探し、GIS形式を変換し、座標系を合わせ、計算格子と境界条件を作り、解析ソフトを動かすのはかなり大変です。

このツールの目的は、その間をつなぐ作業をできるだけ自動化し、**場所と雨量を選ぶところから始められるようにして、専門ツールを組み合わせる最初のハードルを下げること**です。

# 自分が気になる場所を調べる

![東京駅を中心に解析条件を入力する画面](https://raw.githubusercontent.com/nobunora/qiita-articles/master/public/images/urban-pluvial-flood-simulator-v0117/tokyo-station-setup-v2.png?v=20260928b)

*東京駅を中心に±250 mの解析範囲を指定した例です。住所検索だけでなく、地図クリックや緯度・経度の直接入力でも場所を選べます。*

基本操作は次のとおりです。

1. ZIPをすべて展開し、`UrbanPluvialFloodSimulator.exe` を起動する
2. 住所検索、地図クリック、または緯度・経度入力で中心点を決める
3. 解析範囲と最小ブロックを選ぶ
4. 雨量強度と継続時間を入力する
5. 必要なら「標高のみ取得」で地形を先に確認する
6. 「解析開始」を押す
7. 完了後、時刻スライダーと表示ボタンで結果を見る

住所検索には、東京大学空間情報科学研究センターの「CSISシンプルジオコーディング実験」を利用します。住所ではなく地図を直接クリックして場所を決めることもできます。

## 解析前に標高だけを見る

![四日市の解析領域の標高プレビュー](https://raw.githubusercontent.com/nobunora/qiita-articles/master/public/images/urban-pluvial-flood-simulator-v0117/yokkaichi-elevation-v2.png?v=20260928b)

*四日市サンプルと同じ解析領域の標高表示です。解析範囲内の最低値と最高値を基準に色分けしています。*

「標高のみ取得」は、SFINCS解析を始めずに、指定範囲の標高を取得して表示します。

解析領域内の最低標高から最高標高までをレインボーカラーで8分割するため、絶対標高だけでは分かりにくい小さな高低差も確認できます。まず広めの地図で標高を調べ、低くなっている道路や宅地など、気になる箇所へ解析範囲を絞る使い方もできます。

# 結果の見方

![四日市の浸水深と地点確認](https://raw.githubusercontent.com/nobunora/qiita-articles/master/public/images/urban-pluvial-flood-simulator-v0117/yokkaichi-result-60min-v2.png?v=20260928b)

*四日市サンプルの60分時点の浸水深表示です。*

- **時刻別浸水深**：雨が続くにつれて、どこから水がたまり始めるかを見る
- **最大浸水深**：解析時間内に各場所で到達した最大値を見る
- **ベクトル**：矢印の向きで流向、色や大きさで流速を見る
- **粒子フロー**：ベクトル場に沿って移動する粒子から、連続した流れを直感的に見る
- **標高**：解析範囲内の相対的な高低差を見る
- **計算格子**：どの解像度で扱われたかを見る
- **地点確認**：地図をクリックし、その場所の値を確認する

粒子の移動速度には流速を反映しています。粒子は複数のベクトル間を補間して移動し、寿命の位相もずらしているため、一斉に現れて一斉に消える表示にはしていません。

# 解析範囲とメモリに注意

解析範囲を広げ、ブロックを細かくすると、セル数は急激に増えます。幅と高さを2倍にすると、同じ格子寸法ではセル数は約4倍です。

| 条件 | おおよそのセル数 | 画面に表示する概算ピークメモリ |
|---|---:|---:|
| ±250 m、1 m格子 | 25万 | 約0.6～1.2 GB |
| ±500 m、1 m格子 | 100万 | 約1.0～2.0 GB |
| ±1000 m、1 m格子 | 400万 | 約2.4～4.8 GB |
| ±2000 m、1 m格子 | 1600万 | 約8.1～17 GB |
| ±4000 m、1 m格子 | 6400万 | 約31～62 GB |

地物数や実行環境によって増減しますが、広い領域を1 m格子にすると数十GB単位のメモリが必要です。メモリ不足になると解析が極端に遅くなったり、失敗したりします。

最初は **±250～500 m、1 m格子** で試し、広げる場合は2 mまたは4 m格子を選ぶことを勧めます。アプリの「2. 実行状態」には、実行前からセル数と概算必要メモリを表示します。

# アプリ内部で行っている処理

利用者が入力するのは場所、範囲、格子、雨量、時間ですが、内部ではおおむね次の処理を行います。

1. 緯度・経度と範囲から解析領域を作る
2. 国土地理院の標高データを取得し、欠損を確認して計算格子へそろえる
3. PLATEAUとOpenStreetMapから建物・道路形状を取得する
4. 建物を水が通れない領域として扱い、道路などに粗度を設定する
5. 屋根へ降った雨量を失わないよう、周囲の地表へ再配分する
6. 入力雨量からSFINCS用の降雨時系列と境界条件を作る
7. HydroMT-SFINCSでモデルを構築し、自前ビルドしたSFINCSを実行する
8. NetCDF結果から浸水深・標高・流速を必要な表示範囲だけ読み出す
9. ブラウザ上で浸水深、矢印、粒子、地点値として重ねて表示する

大きな結果を一度にブラウザへ展開するとメモリを使い切るため、現在の表示範囲と時刻に必要な部分だけを読み、上限付きキャッシュへ保存しています。解析済みZIPではSFINCSの `sfincs_map.nc` を正本として保持します。

# もっと細かく設定したい場合

このWindowsアプリは、一般の人が最初の解析まで進みやすくするため、条件をかなり絞っています。

より高度な評価が必要なら、[本ツールのソースコード](https://github.com/nobunora/urban-pluvial-flood-simulator)、SFINCS、HydroMT-SFINCSを直接使い、目的に合わせて拡張できます。例えば次のような内容です。

- 時間的・空間的に変化する降雨
- 土地利用ごとの粗度や浸透
- 下水道、排水ポンプ、雨水桝
- 河川流量、水位、潮位、高潮との境界条件
- 陸橋、アンダーパス、トンネルなど立体交差の個別モデル化
- 可変解像度格子やサブグリッド
- 観測浸水域との比較・パラメータ調整
- NetCDF結果のGISソフトやPythonによる独自解析

これらは入力データの品質確認やモデル校正も必要になるため、設定項目を増やせば自動的に正確になるわけではありません。重要な判断に使う場合は、水理・地形・地域排水を理解した専門家による確認が必要です。

# おわりに

このツールは「ここは安全」「ここは必ず浸水する」と判定するものではありません。

公的な内水評価がない場所や、既存マップとは異なる短時間豪雨を考えたいときに、まず標高を見て、同じ仮定で場所を比較し、次に何を詳しく調べるべきか考えるための入口を目指しています。

親戚の浸水をきっかけに感じた「自分でも周辺地形と水の動きを少し確かめたい」という疑問に対し、公開されているデータと研究成果を、専門環境を一から構築しなくても試せる形へまとめました。

結果は参考程度にとどめ、実際の避難情報や防災判断では、自治体、気象庁、国土交通省などの公式情報を優先してください。
