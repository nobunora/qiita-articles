# はじめに

32bit float対応レコーダーで録音すると、録音時のピーク割れにかなり強くなります。

一方で、録った後に聞くと、

- 声が小さい
- 場面ごとの音量差が大きい
- PCやDAWを開くほどではないが、共有前に聞きやすくしたい
- iPhoneだけで処理したい

ということがよくあります。

そこで、WAVファイルをブラウザ内だけで解析・補正し、補正済みWAVとして保存する **Offline Float Leveler** を作りました。

- アプリ: https://float-leveler.web.app
- GitHub: https://github.com/nobunora/float_leveler
- 詳細説明: https://float-leveler.web.app/about.html

# 何を作ったか

Offline Float Levelerは、WAVを読み込んで、入力と出力の音量を比較しながら補正できるブラウザアプリです。

主な機能は以下です。

- WAV解析
  - Sample rate
  - Format
  - Channels
  - Duration
  - Peak
  - Over 0dBFS
  - Integrated LUFS
- WAV処理
  - LUFS補正
  - 一括ゲイン
  - 窓ごとの自動フェーダー補正
  - DCオフセット除去
  - リサンプル
  - ディザ
  - クリップ処理
- 入力/出力比較
  - 処理前と処理後の値を左右に表示
  - LUFS、Peak、Gainのグラフ表示
  - レポート保存
  - サマリーコピー

音声ファイルはサーバーへアップロードせず、ブラウザ内のWeb WorkerとWASMで処理します。

# なぜ作ったか

32bit float録音は便利ですが、録音後の音量調整は意外と面倒です。

特に、リハ、練習、インタビュー、フィールド録音のような用途では、

- 本格的な編集ではなく、まず聞ける状態にしたい
- なるべく早く共有したい
- スマホだけで済ませたい
- 録音データを外部サービスへ投げたくない

というニーズがあります。

このツールは、音楽制作の最終マスタリングではなく、録音後の「聞きやすい確認用WAV」を素早く作ることを狙っています。

# 使い方

基本操作はシンプルです。

1. 用途プリセットを選ぶ
2. `開いて解析` または `開いて処理` を押す
3. WAVファイルを選ぶ
4. 入力と出力の値を確認する
5. `補正済みファイルを保存` でWAVを保存する

用途プリセットは以下です。

- 会話等音量フラット
  - 会話、インタビュー、ポッドキャスト、スマホ再生向け
- 音楽
  - リハ、練習、セッション録音の確認用
- 自然音
  - フィールド録音や環境音向け
- カスタム
  - ユーザーが保存した処理値を使う

# 処理の考え方

このツールは、ピークを瞬間的に潰すリミッターというより、録音後にフェーダーを動かすような考え方で音量を整えます。

中心になるのは以下の2つです。

## 一括レベル補正

ファイル全体に同じゲインをかける方式です。

自然音のように元の強弱を残したい素材や、録音全体を単純に持ち上げたい場合に向きます。

## 窓ごとの補正

0.1〜10秒の解析窓ごとにLUFSやPeakを測り、区間ごとにゲインを変える方式です。

短い窓ほど細かく追従し、コンプ的な効き方に近づきます。

長い窓ほど自然なフェーダー操作に近くなります。

現在は、解析窓同士を75%重ねて見ています。これにより、グラフとゲイン変化が急になりすぎないようにしています。

処理の重い部分をRust/WASMへ寄せ、画面側はTypeScriptに分けています。

# Rust/WASMにした理由

このツールでは、数百MB級のWAVを扱うことがあります。

TypeScriptだけでも実装はできますが、大きなTypedArrayを何度も処理すると、

- メモリ使用量が読みにくい
- コピーが増える
- GCの影響を受けやすい
- iPhoneブラウザで不安定になりやすい

という不安があります。

Rustなら、処理コアを比較的安全に書きつつ、WASMへコンパイルできます。

将来ネイティブアプリへ移植する場合にも、音声処理コアを再利用しやすいです。

# 32bit float録音との相性

32bit float WAVでは、0dBFSを超えたサンプルも値として保持できます。

ただし、16bit/24bit PCMへ出力する場合は0dBFSを超えた値をそのまま保存できません。

そのため、このツールでは、

- 入力Peak
- Over 0dBFS
- 出力Peak
- クリップ処理サンプル数
- クリップが発生した窓数
- クリップ前の最大超過量

を表示して、処理結果を確認できるようにしています。

# プリセットの方向性

## 会話等音量フラット

会話、インタビュー、ポッドキャスト、スマホ再生向けです。

小さい声をかなり持ち上げ、聞き取りやすさを優先します。

Target LUFSは-14です。

## 音楽

リハや練習音源の確認用です。

48kHz / 24bit PCM出力で、音楽の強弱をなるべく残しつつ、過大ピークを安全側に収める方向です。

音楽制作の最終マスタリングではなく、仲間に共有する確認音源を作る用途を想定しています。

## 自然音

自然音、環境音、フィールドレコーディング向けです。

10秒窓と一括ゲイン寄りの処理で、鳥の鳴き声や突発音で音量がふわふわ動くことを避けます。

小さな環境音は聞きやすく持ち上げつつ、ジェットエンジンのような過大入力はPCMの範囲へ収めることを狙っています。

# 大容量WAV対応

標準の読み込み上限は300MBです。

これはiPhoneなどのスマホで安定して処理するための安全側の値です。

カスタム処理値の最後にある `読み込み上限` を変更すると、PC等向けに1GB、2GB、3GB、4GBまで選べます。

ただし、これは「読み込みを許可する上限」であって、必ず処理完走できるという意味ではありません。

ブラウザ内では、

- 入力WAV
- デコード後のfloat配列
- 解析データ
- 出力WAV

を同時に保持する場面があります。

そのため、実際に必要なメモリはファイルサイズの数倍になることがあります。

このあたりは、将来的にはチャンク処理やストリーミング解析を検討したいところです。

# Firebase Hostingで公開

公開先はFirebase Hostingです。

静的サイトとして置けるので、WASM、JS、CSS、HTMLだけで配信できます。

URLも短くしたかったので、最終的に以下にしました。

https://float-leveler.web.app

音声処理はブラウザ内で完結するため、サーバー側で音声ファイルを受け取るAPIはありません。

# アクセス解析について

音声ファイルを外へ送らない思想と相性が良いのは、まずFirebase HostingのWebリクエストログを見る方法です。

Google Analyticsを入れるとイベント計測はしやすくなりますが、今回は最初から細かいユーザー行動を取るより、

- どのURLが見られたか
- どのくらいアクセスがあるか
- 404やエラーが出ていないか

くらいから見るのがよさそうです。

Cloud Loggingへリンクすると、Hostingの `webrequests` ログを見られます。

# まとめ

Offline Float Levelerは、

- 32bit float WAVを扱う
- ブラウザ内だけで処理する
- 入力と出力を比較する
- iPhoneでも使える
- Rust/WASMで重い音声処理を行う

という方向で作った音量補正ツールです。

まだ改善したいところはあります。

- より本格的なTrue Peak推定
- チャンク処理による大容量WAV対応
- グラフの見やすさ改善
- プリセットの調整
- アクセスログや利用状況の把握

ただ、実際にiPhoneでもWAVを読み込んで、解析し、補正済みファイルを保存できるところまでは到達しました。

32bit floatレコーダーで録った音を、PCを開かずにさっと聞きやすくしたい用途には、かなり便利になってきたと思います。
